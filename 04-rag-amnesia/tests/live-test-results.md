모든 실행에서 run·각 호출의 backend가 선택값과 일치했습니다. 메모리 모드 1턴의
실제 응답 파일과 2턴 memory_injected가 일치했고, 일반 모드 2턴에는 이전 답변을
별도로 전달하지 않았습니다. Copilot은 실제 응답 모델을 보고했으며 Cursor·agy·Codex는
현재 JSON 형식에서 실제 모델 이름을 제공하지 않아 임의로 채우지 않았습니다.

웹 브라우저에서 실행 중 CLI·Top K 선택 잠금, 도구 변경 시 결과 초기화, 새로고침 후
마지막 Codex 실행의 선택값 복원, 데스크톱·390px 폭의 메뉴 배치도 확인했습니다.

공통 어댑터에 제공된 기록만 한 문장으로 요약하는 별도 질의도 각 CLI에서 성공했습니다.
초기 점검에서 발견한 Cursor의 --trust 필요와 agy의 --print=본문 요구를 반영한 뒤
다섯 도구 모두 실제 성공을 확인했습니다.

응답 내용과 기준 언급 수는 실행마다 달라질 수 있습니다. 이 검증은 선택·호출·파일
전달 동작을 확인한 것이며, 모델 품질 순위나 일반적인 메모리 효과를 입증하지 않습니다.
CLI 버전, 사용자 기본 모델·정책·인증 상태가 다른 환경의 성공을 보장하지 않습니다.
Windows에서 실제 CLI 실행은 검증하지 않았습니다. Windows Copilot 네이티브 실행 파일
선택은 단위 테스트로 확인했습니다. 실제 원문 응답·사용량은 로컬의 ignored memory/에만 둡니다.
