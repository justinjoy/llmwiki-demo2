# 예상 결과 참고 예시

실제 에이전트 실행 결과가 아닌 수동 작성 예시입니다. 실습 후 비교용이며 정답 문구를 그대로 재현할 필요는 없습니다. 아래 원본 링크는 이 예시 파일 기준입니다. 내용을 다른 폴더로 옮길 때는 상대 경로를 조정하세요.

## 첫 ingest 후

`wiki/sources/project-brief.md`에는 문서 일자 2026-11-02, 초기 운영안 승인 상태, 목표·운영·미확정 사항이 요약되어야 합니다.

`wiki/topics/training-project.md`에는 30명, 2026-11-20, 대면 4시간과 [초기 운영안](../raw/01-project-brief.md#operation)의 근거가 있어야 합니다. [교육 목표](../raw/01-project-brief.md#goal)와 강사·장소 미정 상태도 보존합니다.

## 두 번째 ingest 후의 주제 페이지 내용 예

| 항목 | 현재 기록 | 근거와 상태 |
| --- | --- | --- |
| 목표 | AI 초안 작성 후 사람이 근거와 오류 확인 | [초기 목표](../raw/01-project-brief.md#goal), [유지 결정](../raw/02-meeting-notes.md#decision) |
| 일정 | 2026-11-27로 변경. 이전 일정은 11월 20일 | [변경 승인](../raw/02-meeting-notes.md#decision) |
| 인원 | 초기 승인 30명 / 확대 제안 60명. 최종 인원 확인 필요 | [초기 운영안](../raw/01-project-brief.md#operation), [미승인 제안](../raw/02-meeting-notes.md#proposal) |
| 방식 | 초기 승인 대면 4시간 / 변경 제안 온라인 2시간. 최종 방식 확인 필요 | [초기 운영안](../raw/01-project-brief.md#operation), [미승인 제안](../raw/02-meeting-notes.md#proposal) |
| 강사·장소 | 강사 미정, 대면 유지 시 장소 확정 필요 | [남은 확인 사항](../raw/02-meeting-notes.md#open) |

확인 질문: “운영 책임자가 60명·온라인 2시간 제안을 승인했는가? 대면을 유지한다면 장소는 어디인가?”

이 표는 두 번째 원본 요약만 추가해서는 얻을 수 없습니다. 기존 주제의 일정과 충돌 절도 갱신해야 합니다. 승인된 변경과 미승인 제안을 함께 ‘최신 확정안’으로 묶으면 안 됩니다.

## 질문 답변 예

일정은 [변경 승인에 따라 11월 27일](../raw/02-meeting-notes.md#decision)입니다. 방식은 [초기 승인안의 대면 4시간](../raw/01-project-brief.md#operation)이 있으나 [온라인 2시간 제안](../raw/02-meeting-notes.md#proposal)도 있어 최종 확인이 필요합니다. 안내문 발송 전에는 최종 인원·교육 방식, 강사, 대면 유지 시 장소와 발송일을 확인해야 합니다. [회의록](../raw/02-meeting-notes.md#open)에는 이를 모두 확정했다는 근거가 없습니다.

실제 답변에서는 생성된 위키 페이지에도 링크하여 종합 과정과 원본을 모두 따라갈 수 있어야 합니다. 저장을 요청했다면 `wiki/answers/launch-checklist.md`가 생기고 index에도 연결됩니다.

## Lint 결과 확인

- index에서 원본 요약 2개와 주제 1개, 저장했다면 답변 페이지까지 열립니다.
- 원본 요약과 주제가 서로 연결되고 주장별 출처 링크가 열립니다.
- 30명/60명, 대면/온라인의 차이와 확인 질문이 남아 있습니다.
- 일정은 변경되었으나 이전 일정과 승인 근거도 추적할 수 있습니다.
- log는 실제 수행 순서대로 추가되며 raw는 변경되지 않습니다.

이 조건은 검토 기준이며 lint를 실제 수행했다는 기록이 아닙니다. 구조 점검을 통과해도 의미적 정확성은 사람이 원본과 대조해야 합니다.
